badgR security tiers for R code, using flowR's static analysis
Runs locally. Your code is analyzed in this browser and is never uploaded.
How to check

flowR, compiled to JavaScript and WebAssembly, runs in a web worker of this page. The page makes only these requests:

  • its own files: the page, its scripts, and the two WebAssembly parsers,
  • the data of each R package your code loads, from pkgs/<package>.json on this site, so the request names the package but carries none of your code,
  • and only when you ask for it, the GitHub repository or URL you enter. These requests only download.

The page's content security policy, enforced by the browser, allows scripts only from this site and blocks form submissions. Uploaded files are read in the browser with the File API, and report downloads are made in the browser too.

The test suite (test/web.test.ts) opens this page in headless Chromium, analyzes uploads, pasted code, and a GitHub repository, and records every request. It fails when a request goes to any host but this site and the GitHub hosts of the requested repository, uses a method other than GET, or has a body.

To check it yourself, open the network tab of your browser's developer tools while you analyze, or go offline after the page has loaded and analyze an upload.

badgR reads .R, .Rmd, .qmd, .Rprofile, DESCRIPTION, and NAMESPACE files and skips renv and .git folders.

badgR reads repositories, folders, and files on GitHub and GitLab, gists, CRAN packages by name or page (glue, glue@1.8.0, cran:glue, from their GitHub mirror), Bioconductor packages (bioc:limma), and links to the flowR playground or to this page, which carry the code in the link. A plain owner/repo means GitHub. Other servers must allow cross-site downloads (CORS).

Tier changes apply at once; others need a new analysis. The policy stays in this browser; a link to a result carries it along.
